# 批判的レビュー記録: 出発日未超過タスクが早期完了に移行する不具合修正

## 1. 計画時レビュー

### ロール: SE / PG

- **評価**: 妥当。
- **指摘事項**:
  1. キー名問題（`:outbound` と `:outbound-date`）は、片方のみの変更だと他のコンポーネント（ビュー層など）で回帰バグが発生するリスクがあるため、`dto.clj` や `modals.clj`、`dashboard.clj` など全体を漏れなく確認し、両方のキーを相互フォールバックできるようにしつつ、生成時は両方のキーを含めるか統一する必要がある。
  2. タイムゾーン問題について、システムが JST（UTC+9）を標準運用基準としているため、`DateTime/UtcNow` から直接 `DateOnly` を取得している箇所（特に `api_controller.clj`）を一律で JST 変換を通す共通関数を作成して適用すべき。
  3. 既存の `flight_tracker.db` に既に保存されてしまっている該当タスク（`HND ➔ MNL` など）についても、修正後に再度不整合を起こさないか確認・考慮すること。

### ロール: ユーザー

- **評価**: 妥当。
- **指摘事項**:
  - 自然言語や手動で登録した監視タスクが勝手に「完了」になってしまうと、メールやWebhookの通知も一切届かなくなるため、最優先で修正し、正しく巡回されるようにしてほしい。

---

## 2. 実装・検証後レビュー

### ロール: SE / PG

- **評価**: 合格。
- **検証結果**:
  1. キー名問題（`:outbound` と `:outbound-date`、`:inbound` と `:inbound-date`）について、DTOレイヤー（`task->row`, `row->task`）、Webレイヤー（`api_controller`, `modals`, `dashboard`）、およびInfraレイヤー（`scraping_worker`, `google_flights_scraper`, `skyscanner_scraper`）のすべてにおいて双方向フォールバック対応および生成時の両方設定が実施された。
  2. タイムゾーン問題について、JST（UTC+9）を基準とした現在日取得ヘルパー（`get-jst-today`）が `api_controller` および `dto` に導入され、深夜帯（00:00〜08:59 JST）に前日日付（昨日）へフォールバックする問題が根本解決された。
  3. 全22テスト名前空間、453アサーションが100%成功（Pass）し、リグレッションのないことが確認された。

### ロール: ユーザー

- **評価**: 合格。
- **所感**:
  - 新規タスク登録（手動およびAIアシスト）およびスタンドアロン登録のいずれにおいても、指定した出発日・復路日が確実に保存され、登録直後に勝手に完了ステータスへ移行してしまう不具合が完全に解消されたことを確認した。
