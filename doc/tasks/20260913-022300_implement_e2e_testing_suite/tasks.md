# タスク計画書: PlaywrightによるE2Eテストスイートの構築

- **タスクID**: `20260913-022300_implement_e2e_testing_suite`
- **合意レベル**: **L2 (中規模 - テスト基盤追加・E2E検証パイプライン構築)**
- **ステータス**: **未着手 (Backlog / Planned)**
- **目的**:
  FlightTrackerAI の主要ユーザーシナリオ（フライト登録 ➔ 巡回実行 ➔ 結果表示）がフルスタックで正しく動作することを自動テストで担保する E2E テスト基盤を構築する。Web UI（HTMX/Tailwind）、HTTPサーバー、SQLiteデータベース、Playwright実ブラウザスクレイパー、定期巡回ワーカーを統合した End-to-End シナリオを網羅し、UI/バックエンド連携の不整合やリグレッションを自動検知・防止する。
  > **副次的効果**: ClojureCLR の DLR（動的言語ランタイム）に起因する .NET Interop の実行時エラー（C#デフォルト引数の渡し忘れ、`Task<T>` 型ヒント問題等）も、E2Eテストの実行過程で自然に検出できる。

---

## 1. 背景と課題

1. **フルスタックシナリオの検証不足**:
   - 「Web画面からフライト登録 ➔ 巡回実行 ➔ 実ブラウザ起動・DOM抽出 ➔ キャプチャ保存 ➔ SQLite保存 ➔ 最安値判定 ➔ Webhook通知 ➔ HTMX画面反映」という一連のユーザー体験が正しく連動することを自動テストで担保できていない。
   - 複数コンポーネント間（Web, Infrastructure, Core）の結合点にリグレッションリスクがある。
2. **単体テストと実運用環境のギャップ**:
   - 単体テスト（`./scripts/test.ps1`）は高速性・オフライン実行を重視し、外部通信や実ブラウザ起動をバイパス・モックしているため、実ブラウザ連携コードパスの検証が不足していた。
3. **副次的効果: DLR 実行時エラーの早期検出**:
   - ClojureCLR の動的型付け・DLR の特性上、`dotnet build` は `.clj` コードを静的型チェックしない。メソッド引数の個数違いや型不整合はコード実行時に初めて発覚するため、E2Eテストで実コードパスを通すことで副次的にこれらの問題も検出できる。

## 2. 実装計画・スコープ

### 2.1 E2E テストシナリオ
1. **Playwright ライフサイクル・スモークテスト**:
   - Playwright インスタンス初期化 ➔ PersistentContext 起動 ➔ ページ生成 ➔ ステルススクリプト適用 ➔ ページクローズ ➔ コンテキストクローズ ➔ Dispose の正常完走。
2. **Web UI 操作シナリオ**:
   - ヘッドレス/有頭ブラウザからテスト用 Web サーバー (`http://localhost:[test-port]`) へアクセス。
   - ダッシュボード表示確認。
   - 「新規タスク登録」モーダルを開き、全12項目を入力して保存 ➔ 一覧への即時反映（HTMX）。
   - 「AIフライト解析」モーダルを開き、自然文を入力して解析 ➔ パラメータ引き継ぎ登録の検証。
   - システム全体設定画面の保存と復元。
3. **巡回パイプライン結合シナリオ**:
   - 画面の「今すぐ巡回」ボタン押下 ➔ API `/api/tasks/:id/run` 呼び出し。
   - バックグラウンドで Playwright が起動し、スクレイピング実行。
   - スクリーンショット（`doc/work/screenshots/`）が生成されることの検証。
   - DB に実行ログ（`run_logs`）およびスナップショット（`flight_snapshots`）が保存されることの検証。
   - 最安値更新および Webhook 通知（モックHTTPレシーバー）の送達検証。

### 2.2 テスト実行環境と分離方針
- **単体テストとの完全分離**:
  - 日常の高速TDD開発（`./scripts/test.ps1`）には影響を与えず、独立したスクリプト `./scripts/test-e2e.ps1` として提供。
  - テストコード配置: `test/FlightTrackerAI.Web.Tests/e2e/` または `test/FlightTrackerAI.Infrastructure.Tests/e2e/`
- **実行制御**:
  - `$env:RUN_E2E = "true"` などの環境変数によるオプトイン。
  - `--headless` フラグ（CI環境用）および `--headed` フラグ（ローカルデバッグ・目視確認用）のサポート。
