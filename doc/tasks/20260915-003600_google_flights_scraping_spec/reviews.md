# 批判的レビュー記録: Google Flights スクレイピング仕様の刷新と不整合修正

## レビュー日: 2026-09-15

---

### 1. ユーザーロール批判的レビュー (観点: 操作性、要件充足、実用性)

- **指摘 1 (時間レンジの指定UI)**:
  - 「出発時間(レンジ)」「到着時間(レンジ)」について、ユーザーが手動入力する際に細かすぎるスライダーや時刻指定を強制されると使いづらい。「指定なし」「早朝(0:00-6:00)」「午前(6:00-12:00)」「午後(12:00-18:00)」「夜(18:00-24:00)」のようなプリセット選択と、任意時刻指定（例: 9:00〜18:00）の両方が選べる直感的なUIであることが望ましい。
- **指摘 2 (取得件数と画面の整合性)**:
  - 取得件数がデフォルト 10 件の場合、Google Flights の初期画面（「おすすめの往路便」3〜5件）だけでなく、「他のフライトを見る」のセクションも含めて上位10件が取得されることになる。スクリーンショットには、そのうちの最安値（1位の便）が確実に画面内に見えている状態で保存されないと、「また金額と画像がズレている」と感じてしまう。
- **指摘 3 (片道と往復での到着日・到着時間)**:
  - 片道検索時は「到着日」「到着時間レンジ」の入力が不要（または片道便の到着時刻レンジを意味するのか）が混同されやすい。往復時の「復路出発日/復路時間帯」なのか、各レグの「到着時刻」なのかを用語として画面上で分かりやすく整理してほしい。

---

### 2. SE/PGロール批判的レビュー (観点: 技術的実現性、堅牢性、保守性)

- **指摘 1 (Google Flights の URL パラメータ vs DOM 操作)**:
  - Google Flights は初期URL（`travel/flights?q=...`）である程度の条件（出発地、目的地、日付）を渡せるが、時間レンジや経由地数フィルターを確実に適用するには、画面ロード後に Playwright でフィルターバー（`button[aria-label*='経由地数']`、`button[aria-label*='時刻']`）を操作するか、あるいは Google Flights 内部のエンコードURL（protobuf base64形式）を使う必要がある。
  - セレクタ操作（2段階目の検索）で行う場合、ポップアップやオーバーレイ（Cookie同意、アニメーション完了待機）を考慮し、PointerEventsIntercepted 例外を避けるための安全な待機（`WaitForSelectorAsync`、`ClickAsync(Force=true)`、`WaitForTimeoutAsync`）を徹底すること。
- **指摘 2 (DOM セレクタの単一カード化と価格パース)**:
  - HTMLサンプルの解析により、カード要素は `li.pIav2d`（28件）で一意に特定できることが確認された。
  - 価格は `span[aria-label*='円']` の属性値（例: `34527 円`）またはメタ要素 `div.JMc5Xc[aria-label]`（例: `往復の合計金額 34527 円～`）から正規表現 `r"(\d+)\s*円"` で抽出することで、時刻要素（`8:50 – 15:15`）の誤認バグを完全に排除できる。
- **指摘 3 (データベース・DTO の後方互換性)**:
  - タスクテーブル（`tasks`）に「出発時間レンジ」「到着時間レンジ」「取得件数」などのカラムを追加するマイグレーションが必要。既存のタスクがエラーなく動作するよう、NULLまたはデフォルト値（例: レンジ指定なし、取得件数10件）を適切に扱うこと。

---

### 3. 指摘への対応方針

1. **時間レンジの表現**:
   - `outbound-time-range` / `inbound-time-range` をドメインに導入。
   - `Any` (指定なし)、または `{:start "06:00" :end "12:00"}` などの構造で柔軟に保持。
   - 画面上はプリセット（午前・午後・夜間等）およびカスタム時刻範囲の入力に対応。
2. **2段階検索の実装**:
   - 1段階目: URL 遷移による基本検索。
   - 2段階目: 経由地数ボタンをクリックし、`指定なし` / `直行便` / `1箇所まで` のラジオを選択。
   - ソート順: 「並べ替え」ボタンで「料金が安い順」を選択（または「最安値」タブ）。
   - 抽出: `li.pIav2d` を走査し、上位 N 件（設定値、デフォルト10件）を抽出。
   - キャプチャ: フィルターとソートが適用された直後の最安値便が見える状態で撮影。
3. **既存データへの配慮**:
   - DB マイグレーションは `database.clj` に `ALTER TABLE tasks ADD COLUMN ...` を冪等に追加。
4. **画面キャプチャのウィンドウサイズ定義**:
   - ウィンドウサイズ（ViewportSize: 1440x900 等）を明示的に定数/設定値として定義し、全画面ではなくブラウザウィンドウ表示領域と 1:1 のサイズでキャプチャを保存。
5. **便名（Flight Number）の完全抽出と同一航空券キー（`flight_key`）**:
   - ユーザー指摘に基づき、各カードの `itinerary=...` 属性から各レグの便名（例: `5J 5055`, `NH 869`, `PR 431`）を抽出し、同一航空券判定キー `flight_key`（`task_id` + `flight_numbers` + `outbound_date`）を導入。日々の同一航空券の価格追跡を 100% 正確に実現。
