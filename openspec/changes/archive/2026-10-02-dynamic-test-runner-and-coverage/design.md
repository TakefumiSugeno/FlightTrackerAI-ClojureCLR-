# Design

## Context

FlightTrackerAI は ClojureCLR (.NET 10) を採用しており、ソースコードおよびテストコードはコンパイル時ではなく、`dotnet clojure.main` の実行時に動的に評価・ロードされます。
現状の `test/test_runner.clj` では、テスト名前空間が配列として固定列挙されており、カバレッジレポート（`generate-coverage-html`）には架空の静的データ（94.9%）が直接記述されています。
本設計では、外部バイナリツールに依存せず、ClojureCLR ランタイムの機能を最大限に活用して、動的テスト探索と正確なコードカバレッジ計測を実現します。

## Goals / Non-Goals

**Goals:**

- `test/` 配下の `*_tests.clj` を走査し、テスト名前空間を自動抽出・ロード・実行する機構の実現。
- `src/` 配下の `*.clj` を走査し、全 Var（関数・マクロ）を `alter-var-root` で動的ラップしてテスト実行中の呼び出しを記録する実測カバレッジ機構の実現。
- 各モジュールの有効コード行数（空行・コメント行を除く）および実行行数から、正確な行カバレッジ（%）を算出し、`CoverageReport.html` に出力する。
- 実行された全テストスイート、テストケース（`deftest`）、アサーション（Pass/Fail/Error）、所要時間を整理した `TestResults.html` の生成。
- `scripts/test.ps1` の文字コード・環境互換性（Windows PowerShell 5.1 および pwsh 7）の確保。

**Non-Goals:**

- AST（抽象構文木）を全面的に書き換えるコンパイラレベルのコード変換（Var レベルのトラッキングと行マッピングで十分な精度を確保）。
- サードパーティ製 IL プロファイラ（Coverlet 等）の強制導入（ClojureCLR の動的ロード環境では動作しないため）。

## Decisions

### Decision 1: 動的 Var インストルメンテーション + ソース行解析方式

- **選択肢**:
  1. **動的 Var インストルメンテーション (採用)**: `alter-var-root` で全 Var を実行カウンタ付き関数でラップし、Var のメタデータ（`:line`）とソースファイルの有効行数をマッピングして行カバレッジを算出。
  2. 式レベル AST 書き換え (Cloverage 方式): ソースコードの全フォームを書き換えて `eval` する。
  3. .NET Coverlet: アセンブリの IL を解析する。
- **決定理由**:
  ClojureCLR はソースコードを実行時に動的評価するため、Coverlet は動作しません。また式レベルの AST 書き換えはマクロ展開や特殊構文で破壊的リスクが高い一方、Var インストルメンテーションは Clojure 標準の関数操作だけで 100% 確実に動作し、高速かつ安全です。
- **行カバレッジ算出アルゴリズム**:
  1. ファイルの全行から、空白行および行頭 `;`（コメント行）を除外し「有効コード行（Executable Lines）」を抽出。
  2. 各 Var の `:line` メタデータを取得し、行番号順にソートして各関数の行範囲を決定。
  3. テスト実行中に呼び出し回数が 1 以上の Var がカバーする有効行を「実行済み行（Covered Lines）」とカウント。
  4. カバー率 = (実行済み行数 / 有効コード行数) * 100。

### Decision 2: ファイルシステム走査によるテスト・ソース名前空間の自動探索

- **選択肢**:
  1. **ファイル走査 + ns 宣言抽出 (採用)**: `Directory/GetFiles` で走査し、ファイル内の `(ns ...)` から正規表現で名前空間シンボルを取得。
  2. 設定ファイル（edn や json）による明示的管理。
- **決定理由**:
  テストやソースを追加・削除した際に設定ファイルやランナーを編集する人的ミスを完全に排除するため、ファイルシステムからの動的自動検出を採用します。

### Decision 3: テストサマリとレポートの表現明確化

- **決定理由**:
  現状の「Total Test Suites」カードに名前空間数（23）が表示され、`deftest`（テストケース）数が見えにくい課題を解消します。
  - Test Suites (名前空間数)
  - Test Cases (deftest 実行数)
  - Assertions (Pass, Fail, Error)
  - Duration (総実行時間)
    を明確に分離して表示します。

## Risks / Trade-offs

- **[Risk] 関数単位のトラッキングによる条件分岐（ブランチ）の未検知**
  - **Mitigation**: 関数の呼び出し自体の有無と、関数のカバー行数を正確に追跡するため、未実行の関数やデッドコードは明確に 0% として検知されます。単体テストが関数単位・仕様単位で書かれている本プロジェクト（1:1 対応規約）において、十分な精度と透明性が担保されます。
- **[Risk] Windows PowerShell (powershell.exe) における UTF-8 文字化け**
  - **Mitigation**: `scripts/test.ps1` を UTF-8 with BOM で保存、またはマルチバイト絵文字を出力する際にエスケープシーケンスに配慮し、構文エラーを防ぎます。
